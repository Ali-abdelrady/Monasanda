# تمامات — إدارة العودة من الإجازات

واجهة React + TypeScript + Tailwind CSS + TanStack React Query لتطبيق إدارة دفعات الإجازات وتسجيل الحضور.

## المتطلبات
- Node.js 20+
- Go API يعمل على `http://localhost:8080`

## التشغيل
```bash
npm install
cp .env.example .env
npm run dev
```

يفضل ترك `VITE_API_BASE_URL` فارغًا في التطوير؛ يقوم Vite بتمرير `/api` إلى `http://localhost:8080` لتجنب مشكلة اختلاف الـ origin. لو غيّرت عنوان الـ API، حدّث `vite.config.ts` أو متغير البيئة حسب طريقة تشغيلك.

## البناء والتحقق
```bash
npm run build
npm run preview
```

## المميزات الموجودة
- تسجيل الدخول عبر `POST /api/login` والتحقق من الجلسة عبر `GET /api/me`.
- قائمة دفعات الإجازات وإنشاء/تعديل/حذف الدفعات.
- ملخص الحضور والغياب ونسبة الحضور.
- جدول وكروت، بحث بالاسم والرقم العسكري والتليفون والسكن، وفلاتر حالة الحضور.
- تسجيل الحضور وإلغاؤه عبر API، مع تحديث تلقائي كل 4 ثوانٍ في صفحة الدفعة.
- إضافة/تعديل/حذف الأفراد وتحديد مجموعة وتصدير المحدد.
- استيراد XLS/XLSX مع معاينة وفحص البيانات وتخطي أرقام عسكرية مكررة داخل الدفعة.
- تصدير Excel مع الأعمدة الأصلية وأعمدة حالة الحضور ووقت الحضور.

## ملاحظات تكامل مهمة
- الخادم الحالي لا يوفّر endpoint لتسجيل الخروج؛ زر الخروج في الواجهة ينهي حالة الواجهة المحلية فقط، ولا يبطل جلسة الخادم. أغلق الجلسة من الخادم أو أضف endpoint logout قبل استخدامه كخروج أمني كامل.
- لا يوجد endpoint جماعي للحذف أو الاستيراد؛ تنفّذ الواجهة الطلبات الفردية مع تقييد التزامن عند الاستيراد.
- التحديث الحالي polling كل 4 ثوانٍ، وليس WebSocket. أضف WebSocket في الخادم إذا أردت إشعارات لحظية دون polling.
- API لا يعيد اسم المستخدم المرتبط بـ `checkedInBy`، لذلك تعرض الواجهة وقت الحضور ولا تخمّن اسم المستخدم.
- عملية حذف دفعة قد تحذف سجلات مرتبطة بها حسب تنفيذ الخادم. راجع سلوك الحذف في الـ backend قبل استخدامه على بيانات مهمة.
- شهادة الحضور/الغياب تظهر كميزة مستقبلية غير منفذة حاليًا؛ زرها يوضح ذلك بدلًا من إنشاء مستند رسمي غير معتمد.

## عقد API المتوقع
تستخدم الواجهة الـ endpoints الموجودة في دليل API: `/api/login`, `/api/me`, `/api/vacation-batches`, و`/api/attendances`. كل طلب يرسل `credentials: 'include'`. يتم إرسال `PUT` بجميع الحقول القابلة للتعديل، بما فيها `phoneNumber`.
